# Non-goals

Этот файл фиксирует то, чего проект не делает в первой архитектурной фазе.

## 1. Не строим SQL-first СУБД

SQL shell не является доказательством существования СУБД. До SQL нужны страницы, WAL, recovery, каталог и минимальная модель транзакций.

## 2. Не используем JSON как формат базы

JSON допустим как debug export или тестовый snapshot. Он не является physical format, page layout, WAL или recovery protocol.

## 3. Не продолжаем `src/core.rs`

Старый `core.rs` сохранён в `docs/legacy/RDBMS-master/src/core.rs`. Он не должен становиться модулем нового ядра.

## 4. Не делаем универсальность через “всё сразу”

Первая версия не обязана поддерживать все типы индексов, сетевой сервер, распределённость, сложный optimizer, columnar storage, полноценный MVCC и внешние плагины одновременно.

## 5. Не стабилизируем внутренние Rust trait как plugin ABI

Rust trait удобен внутри workspace. Для внешних расширений нужен отдельный ABI contract.

## 6. Не начинаем с mmap

MVP должен работать через явный VFS и page IO. mmap можно изучать позже, но он усложняет переносимость и crash reasoning.

## 7. Не обещаем промышленную надёжность

Проект учебно-инженерный. Он может иметь строгие инварианты и тесты, но не должен выдавать себя за промышленную СУБД без долгой проверки отказов, совместимости и безопасности.
