# Devctl patches

Этот проект меняется через devctl-патчи. Патч должен быть самодостаточным: внутри архива лежит `manifest.json`, каталог `files/` с изменяемыми файлами и, при необходимости, краткое описание `PATCH_SUMMARY.md`.

Цель правила простая: каждый шаг разработки должен быть воспроизводимым, проверяемым и пригодным для отката. Ручное копирование файлов в рабочую копию допустимо только для локального эксперимента. Итоговое изменение оформляется патчем.

## Минимальная структура архива

```text
patch_<date>_<slug>.zip
  manifest.json
  PATCH_SUMMARY.md
  files/
    ...пути относительно корня репозитория...
```

`files/` — это корень копирования. Если в архиве лежит `files/docs/architecture.md`, после применения он становится `docs/architecture.md`.

## Обязательные правила manifest.json

`apply.delete` всегда является массивом объектов, а не строк. Нельзя писать так:

```json
"delete": [
  "src/main.rs"
]
```

Нужно писать так:

```json
"delete": [
  { "path": "src/main.rs", "required": false }
]
```

Для каталога указывается `recursive: true`:

```json
"delete": [
  { "path": "src", "recursive": true, "required": false }
]
```

`required: false` используется для совместимых патчей, где путь может уже отсутствовать. `required: true` используется только когда отсутствие пути означает, что патч применяется не к тому состоянию проекта.

`base.branch` должен совпадать с текущей веткой репозитория. Сейчас основная ветка проекта — `master`, поэтому новые патчи по умолчанию должны иметь:

```json
"base": {
  "branch": "master",
  "expectedHead": null
}
```

Если ветка будет переименована, сначала отдельным патчем обновляется это правило и шаблон.

## Checks

Патч обязан объявлять проверки. Для обычного изменения в этом workspace минимальный набор такой:

```json
"checks": [
  {
    "name": "Rust workspace compiles",
    "cwd": ".",
    "command": "cargo check --workspace",
    "requiredCommands": ["cargo"],
    "timeoutSeconds": 300
  }
]
```

Если патч меняет документацию или devctl-правила, добавляется Python-проверка на наличие обязательных документов. Если патч меняет формат файлов, WAL, recovery или ABI, добавляется проверка на синхронность соответствующих документов.

Проверка должна быть простой и локальной. Она не должна требовать сети, внешних сервисов или ручных действий.

## Commit и push

`commit.message` должен быть осмысленным и начинаться с области изменения:

```text
docs: document devctl patch workflow
storage: add page checksum skeleton
wal: add WAL record header model
```

`push.remote` и `push.branch` указываются явно. Для текущего проекта:

```json
"push": {
  "remote": "origin",
  "branch": "master"
}
```

Если патч не должен пушиться, это должно быть явно отражено политикой devctl-запуска, а не неясным manifest.

## Archive policy

Патч не должен включать мусорные или локальные файлы. В `archive.exclude` должны оставаться как минимум:

```json
[
  ".git/",
  "target/",
  "dist/",
  "build/",
  "coverage/",
  "__pycache__/",
  ".env",
  ".env.*",
  "*.sqlite",
  "*.db",
  "*.dbonrs"
]
```

## Dry-run перед применением

Перед запуском конвейера нужно смотреть dry-run. Нормальный dry-run показывает:

- `validation.ok: true` или отсутствие ошибок валидации;
- ненулевое число файлов к копированию, если патч должен добавлять или менять файлы;
- ненулевое число путей к удалению, если патч заявляет удаления;
- объявленные проверки;
- правильную ветку.

Красные флаги:

- `manifest.apply.delete[0] должен быть объектом` — delete записан строками, нужно заменить на объекты;
- `Патч ожидает ветку 'main', текущая ветка — 'master'` — исправить `base.branch` и `push.branch`;
- `Файлов к копированию: 0` при содержательном патче — скорее всего неверный `filesRoot` или файлы лежат не там;
- `Проверки не объявлены` — manifest неполный.

## Локальная проверка manifest

В репозитории есть скрипт:

```bash
python tools/devctl/validate_patch_manifest.py path/to/manifest.json
```

Он проверяет правила, с которыми уже были проблемы: объектную форму `apply.delete`, ветку `master`, наличие `checks`, `commit.message`, `push.branch`, `apply.filesRoot` и базовой archive policy.

Скрипт не заменяет devctl dry-run. Он нужен как быстрый предохранитель до упаковки архива.
