# Development process

Разработка RDBMS идёт короткими проверяемыми шагами. Основной носитель изменения — devctl-патч.

Обязательный порядок:

1. Обновить архитектурный документ, если меняется контракт подсистемы.
2. Внести код или документацию.
3. Оформить devctl-патч.
4. Проверить manifest локально через `tools/devctl/validate_patch_manifest.py`.
5. Прогнать devctl dry-run.
6. Применять патч только если dry-run показывает копируемые файлы, удаления и checks так, как ожидалось.

Для проекта важнее воспроизводимость шага, чем скорость ручного изменения. Особенно это касается storage, WAL, recovery, catalog и extension ABI.

См. также: `docs/development/devctl_patches.md`.
