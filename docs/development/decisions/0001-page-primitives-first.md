# Decision 0001 — первым реализовать slotted page

## Решение

Первым практическим патчем после architecture-first reboot реализуется `rdbms_page`: фиксированная страница, header, slot directory, insert/read/delete/compact и checksum validation.

## Почему не SQL

SQL shell выглядит заметнее, но не создаёт гарантий хранения. Мануал задаёт порядок:

```text
байты → страницы → WAL → каталог → таблица → транзакция → индекс → запрос
```

Поэтому проект сначала получает физическую единицу хранения, а не парсер команд.

## Инвариант

Живой `SlotId` не меняется после `compact()`. Это нужно, чтобы будущий `RowId { page_id, slot_id }` оставался физическим адресом записи.

## Последствия

Теперь можно писать следующий патч: VFS/page store. Он должен сохранять `Page` в файл, читать её обратно, проверять checksum после reopen и обнаруживать повреждённую страницу.
